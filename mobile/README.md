# FreshFlow — мобильное приложение ресторана (Expo / React Native)

Мобильная версия веба: те же 7 разделов и тот же дизайн (индиго-«стекло», светлая/тёмная/системная тема),
плюс **уведомления** о важных событиях.

| Раздел | Что внутри |
|---|---|
| Дашборд | статистика, выручка и заказы по дням, сроки годности, запасы, топ блюд, сигналы |
| Остатки | продукты → раскрывающиеся партии, фильтр по поставке |
| Стоп-лист | блюда и причина («не хватает …») |
| Горячие | приоритетные блюда с объяснением, «В заказ» |
| Заказы | меню с ±, липкая корзина, FEFO-результат, история |
| Поставка | рекомендации к закупке + форма приёма с валидацией как в вебе |
| Списание | просрочка (по одной / всё), аналитика, история |

## 1. Адрес сервера

По умолчанию приложение работает с продовым API: `https://restaurant-production-2e70.up.railway.app/api`
(проверка: `https://restaurant-production-2e70.up.railway.app/health` отвечает `ok`).
Это адрес **Go-бэкенда**; веб-сайт (`magnificent-trust-…`) — другой сервис, его в приложение вписывать не нужно.

Сменить адрес можно без пересборки: аватар → **Настройки → Сервер** (проверяется `/health`, `/api` дописывается сам),
либо через `EXPO_PUBLIC_API_URL` в `eas.json` / `.env`. Используйте **https** — Android в релизных сборках блокирует http.

## 2. Запуск для разработки

```bash
cd mobile
npm ci
cp .env.example .env        # по умолчанию уже указан прод-API
npm start                    # QR-код → приложение Expo Go
```
`localhost` на телефоне — это сам телефон. Эмулятор Android видит компьютер как `10.0.2.2`.

## 3. Сборка приложения, которое можно скачать

```bash
npm i -g eas-cli
eas login
eas init                     # привяжет проект к вашему аккаунту Expo
eas build -p android --profile preview      # → .apk, ссылка на скачивание
eas build -p android --profile production   # → .aab для Google Play
```
* **Android**: `.apk` из профиля `preview` можно отправить ссылкой/QR кому угодно.
* **iOS**: нужен платный Apple Developer ($99/год). `eas build -p ios --profile production`, затем `eas submit` → TestFlight.
* `bundleIdentifier`/`package` в `app.json` — `com.iigiyuuii.restaurant`; поменяйте на свой до первой публикации.

## 4. Уведомления

Настройки: аватар → Настройки → Уведомления (общий выключатель + по типам).
Тап по уведомлению открывает нужный раздел.

| Тип | Когда | Как доставляется |
|---|---|---|
| Срок годности | за 24 ч до конца и когда срок вышел | **планируется на точное время** — сработает и при закрытом приложении |
| Стоп-лист | блюдо ушло в стоп-лист | проверка при открытом приложении + фоновая |
| Закупка | продукт закончился | то же |
| Горячие | появилось срочное предложение | то же |
| Заказы | заказ отклонён (в т.ч. с другого устройства) | то же |

Защита от спама: первый запуск ничего не шлёт; одно событие не чаще раза в 6 ч; пачка → одно сводное уведомление.

**Ограничения (честно):**
* Фоновая проверка (`expo-background-task`) — раз в ≥15 мин и на усмотрение ОС: на iOS бывает реже, не работает после принудительного закрытия приложения, на Android зависит от режима экономии батареи.
* Поэтому уведомления о **стоп-листе/закупке/горячих** не мгновенные. Мгновенными (при закрытом приложении) их сделает только серверный push (Expo Push + таблица токенов и воркер в Go-бэкенде) — это отдельная доработка бэкенда.
* Push на Android не работает в Expo Go; локальные уведомления — работают. Для проверки фона используйте `eas build --profile development`.
